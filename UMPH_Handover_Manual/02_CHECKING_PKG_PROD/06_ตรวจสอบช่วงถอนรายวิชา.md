# 06 ตรวจสอบช่วงถอนรายวิชา

เอกสารนี้ใช้เป็น Checklist สำหรับตรวจสอบระบบก่อนและระหว่างช่วงถอนรายวิชา รวมถึงใช้ติดตามกรณีที่คณบดี (Dean) อนุมัติแล้ว แต่สถานะการถอนยังค้างอยู่

---

## 1. การตรวจสอบก่อนเปิดช่วงถอนรายวิชา

### 1.1 ตรวจสอบข้อมูล Dean

ตรวจสอบรายชื่อและสิทธิ์ของ Dean ว่ามีการเปลี่ยนแปลงจากข้อมูลที่ฝ่ายทะเบียนส่งมาให้หรือไม่

หากมีการเปลี่ยนแปลง ให้ปรับปรุงข้อมูลในตาราง:

```text
AVSREG.WITHDRAW_PERMISSION
```

หลังปรับปรุงควรตรวจสอบอย่างน้อยดังนี้:

- Officer/User ของ Dean ถูกต้อง
- สำนักวิชาหรือขอบเขตที่รับผิดชอบถูกต้อง
- กลุ่มสิทธิ์สำหรับการอนุมัติการถอนถูกต้อง
- สถานะสิทธิ์ยัง Active
- ไม่มีสิทธิ์เดิมที่ซ้ำหรือค้างอยู่

### 1.2 ตั้งค่าปฏิทินช่วงถอนรายวิชา

ตั้งค่าปฏิทินในตาราง `AVSREG.WITHDRAW_CARLENDAR` ให้ตรงกับปีการศึกษาและภาคการศึกษาที่กำลังจะเปิดใช้งาน

ขั้นตอนดำเนินการ:

1. ตรวจสอบว่ามีข้อมูลปฏิทินของปีการศึกษาและภาคการศึกษานั้นแล้วหรือไม่
2. หากยังไม่มี ให้เพิ่มรายการปฏิทินให้ครบตามกลุ่มผู้ใช้งานที่เกี่ยวข้อง
3. ตรวจสอบให้ปีการศึกษา (`ACADYEAR`) และภาคการศึกษา (`SEMESTER`) ถูกต้อง
4. หลังจากเตรียมรายการแล้ว ให้ฝ่ายทะเบียนเข้าไปปรับวันและเวลาเริ่มต้น–สิ้นสุดผ่านหน้าระบบ
5. ตรวจสอบข้อมูลในฐานข้อมูลอีกครั้งหลังฝ่ายทะเบียนบันทึก เพื่อยืนยันว่าวันที่มีผลถูกต้อง

ตัวอย่างคิวรีสำหรับตรวจสอบปฏิทิน:

```sql
SELECT t.*, t.ROWID
FROM AVSREG.WITHDRAW_CARLENDAR t
WHERE t.WITHDRAW_CARLENDAR_ACADYEAR = 2568
  AND t.WITHDRAW_CARLENDAR_SEMESTER = 2
ORDER BY t.WITHDRAW_CARLENDAR_CODE;
```

ข้อมูลสำคัญที่ต้องตรวจสอบ:

- `WITHDRAW_CARLENDAR_CODE` — รหัสกลุ่มปฏิทิน
- `WITHDRAW_CARLENDAR_NAME` — ชื่อกลุ่มผู้ใช้งาน
- `WITHDRAW_CARLENDAR_ACADYEAR` — ปีการศึกษา
- `WITHDRAW_CARLENDAR_SEMESTER` — ภาคการศึกษา
- `WITHDRAW_CARLENDAR_STARTDATE` — วันและเวลาเริ่มต้น
- `WITHDRAW_CARLENDAR_ENDDATE` — วันและเวลาสิ้นสุด

> ชื่อตารางและคอลัมน์ใช้คำว่า `CARLENDAR` ตามโครงสร้างฐานข้อมูลเดิม ให้ตรวจสอบการสะกดก่อนนำไปใช้กับ Environment อื่น

---

## 2. เส้นทางข้อมูลสำหรับตรวจสอบการถอนรายวิชา

ใช้คิวรีต่อไปนี้เพื่อติดตามข้อมูลของนักศึกษาแต่ละราย ตั้งแต่คำขอถอนจนถึงข้อมูลลงทะเบียนและผลการศึกษา ตัวอย่างใช้รหัสนักศึกษา `6731006112`

```sql
-- 1) คำขอถอนและสถานะการอนุมัติ
SELECT t.*, t.ROWID
FROM AVSREG.WITHDRAW_REQUEST t
WHERE t.STUDENTID = 6731006112;

-- 2) Log การปรับปรุงข้อมูลลงทะเบียน
SELECT t.*, t.ROWID
FROM AVSREG.ENROLLSUMMARYLOGUPDATE t
WHERE t.STUDENTID = 6731006112;
-- AND t.CLASSID = 188670;

-- 3) ผลการศึกษา/เกรดของรายวิชา
SELECT t.*, t.ROWID
FROM AVSREG.TRANSCRIPT t
WHERE t.STUDENTID = 6731006112;
-- AND t.COURSEID = 1705228968;
-- AND t.CLASSID = 188670;

-- 4) รายวิชาที่ลงทะเบียนสำเร็จ
SELECT t.*, t.ROWID
FROM AVSREG.ENROLLSUMMARY t
WHERE t.STUDENTID = 6731006112;
-- AND t.CLASSID = 229241;

-- 5) สถานะของนักศึกษา
SELECT t.*, t.ROWID
FROM AVSREG.STUDENTSTATUS t
WHERE t.STUDENTID = 6731006112;

-- 6) Header/ข้อมูลหลักของการลงทะเบียน
SELECT t.*, t.ROWID
FROM AVSREG.ENROLL t
WHERE t.STUDENTID = 6731006112;
-- AND t.CLASSID = 188670;

-- 7) รายการรายวิชาในกระบวนการลงทะเบียน
SELECT t.*, t.ROWID
FROM AVSREG.ENROLLITEM t
WHERE t.STUDENTID = 6731006112;
-- AND t.CLASSID = 188670;
```

### ลำดับการไล่ตรวจสอบที่แนะนำ

1. เริ่มจาก `WITHDRAW_REQUEST` เพื่อตรวจสถานะคำขอและการอนุมัติของแต่ละขั้น
2. ตรวจ `ENROLLSUMMARY` ว่ารายวิชายังคงอยู่ และค่า `GRADE` ถูกปรับเป็น `W` แล้วหรือยัง
3. ตรวจ `TRANSCRIPT` ว่าผลการถอนถูกส่งต่อไปยังประวัติผลการศึกษาหรือไม่
4. ตรวจ `ENROLLSUMMARYLOGUPDATE` เพื่อดูประวัติการปรับปรุง
5. หากกระบวนการไม่สำเร็จ ให้ตรวจ `SUBMIT`, `SUBMITITEM`, `ENROLL` และ `ENROLLITEM` เพื่อหา Error หรือ Lock ที่ค้างอยู่

> ควรเพิ่มเงื่อนไข `ACADYEAR`, `SEMESTER` และ `CLASSID` ทุกครั้งที่ทราบค่า เพื่อไม่ให้ข้อมูลคนละภาคการศึกษาหรือคนละรายวิชาปะปนกัน

---

## 3. ตรวจสอบกรณี Dean อนุมัติแล้ว แต่สถานะถอนยังค้าง

คิวรีนี้ใช้ค้นหารายการที่ Dean อนุมัติแล้ว (`DEAN_STATUS = 'A'`) แต่รายวิชาใน `ENROLLSUMMARY` ยังไม่มีเกรด ซึ่งอาจหมายถึงขั้นตอนปรับสถานะถอนยังทำงานไม่สำเร็จ

```sql
SELECT
    s.*,
    s.ROWID
FROM AVSREG.SUBMIT s
INNER JOIN AVSREG.SUBMITITEM si
    ON si.STUDENTID = s.STUDENTID
INNER JOIN AVSREG.WITHDRAW_REQUEST w
    ON w.STUDENTID = si.STUDENTID
   AND w.CLASSID = si.CLASSID
INNER JOIN AVSREG.ENROLLSUMMARY e
    ON e.STUDENTID = si.STUDENTID
   AND e.CLASSID = si.CLASSID
WHERE w.ACADYEAR = 2568
  AND w.SEMESTER = 2
  AND w.DEAN_STATUS = 'A'
  AND e.GRADE IS NULL;
-- AND e.STUDENTID = 6431006052;
```

### สิ่งที่ต้องตรวจต่อเมื่อพบรายการ

- ตรวจ Error ใน `AVSREG.SUBMIT` และ `AVSREG.SUBMITITEM`
- ตรวจว่าคำขอใน `AVSREG.WITHDRAW_REQUEST` เป็นปีการศึกษา ภาคการศึกษา และ `CLASSID` เดียวกับรายการลงทะเบียน
- ตรวจว่ารายวิชาใน `AVSREG.ENROLLSUMMARY` ยังไม่มีเกรด `W`
- ตรวจ Lock หรือเงื่อนไขอื่นที่ทำให้กระบวนการ Submit ไม่สำเร็จ

> หาก `SUBMIT` หรือ `ENROLLSUMMARY` มีข้อมูลหลายปี/ภาคการศึกษาต่อนักศึกษาหนึ่งคน ควรเพิ่มเงื่อนไข Join ด้วย `ACADYEAR` และ `SEMESTER` ตามชื่อคอลัมน์จริงของแต่ละตาราง เพื่อป้องกันผลลัพธ์ซ้ำหรือจับคู่ผิดรายการ

---

## 4. กรณีติด Error ในระบบ Submit

บางรายการอาจไม่สามารถถอนสำเร็จ เพราะติด Business Rule หรือ Lock ในกระบวนการ `SUBMIT` / `SUBMITITEM` เช่น:

- ถอนแล้วทำให้หน่วยกิตต่ำกว่าเกณฑ์ขั้นต่ำ
- นักศึกษาหรือรายการลงทะเบียนติด Lock
- ติดเงื่อนไขตรวจสอบอื่นของระบบลงทะเบียน

### แนวทางดำเนินการ

1. บันทึกรหัสนักศึกษา ปีการศึกษา ภาคการศึกษา `CLASSID` และข้อความ Error ที่พบ
2. ส่งเคสให้ **พี่โหน่ง** ตรวจสอบและเคลียร์เงื่อนไขหรือ Lock ก่อน
3. หากเป็นกรณีที่ได้รับอนุญาตให้ข้ามเงื่อนไข ให้ดำเนินการผ่านระบบลงทะเบียนเรียนล่วงหน้า หรือกำหนดข้อยกเว้นใน:

```text
AVSREG.ERROR_ABORT_CONFIG
```

4. รันกระบวนการถอนใหม่ แล้วตรวจผลใน `WITHDRAW_REQUEST`, `ENROLLSUMMARY`, `TRANSCRIPT` และ `ENROLLSUMMARYLOGUPDATE`
5. หากเพิ่มข้อยกเว้นชั่วคราวใน `ERROR_ABORT_CONFIG` ให้ตรวจสอบและยกเลิกข้อยกเว้นเมื่อเคสดำเนินการเสร็จแล้ว

> การข้ามเงื่อนไขต้องทำเฉพาะเคสที่ได้รับการยืนยันจากผู้รับผิดชอบ และควรเก็บหลักฐานผู้อนุมัติ เหตุผล และช่วงเวลาที่เปิดข้อยกเว้นไว้ทุกครั้ง

## 5. Checklist สรุป

- [ ] ตั้งค่าปฏิทินใน `WITHDRAW_CARLENDAR` ตามปีการศึกษาและภาคการศึกษา
- [ ] ให้ฝ่ายทะเบียนปรับวันและเวลาผ่านหน้าระบบ
- [ ] ตรวจสอบวันเริ่มต้น–สิ้นสุดในฐานข้อมูลหลังบันทึก
- [ ] ตรวจสอบและอัปเดต Dean ใน `WITHDRAW_PERMISSION`
- [ ] ตรวจสอบคำขอใน `WITHDRAW_REQUEST`
- [ ] ตรวจสอบรายการลงทะเบียนใน `ENROLLSUMMARY`
- [ ] ตรวจสอบเกรด `W` ใน `ENROLLSUMMARY` และ `TRANSCRIPT`
- [ ] ตรวจสอบ Log ใน `ENROLLSUMMARYLOGUPDATE`
- [ ] ตรวจ Error/Lock ใน `SUBMIT` และ `SUBMITITEM`
- [ ] ประสานพี่โหน่งสำหรับเคส Manual
- [ ] ตรวจสอบข้อยกเว้นใน `ERROR_ABORT_CONFIG`
- [ ] ทดสอบซ้ำและยืนยันว่ากระบวนการถอนเสร็จสมบูรณ์

## 6. กรณีส่งอีเมลไม่ได้

บัญชีอีเมลที่ระบบใช้ส่งข้อความ:

```text
coursewithdraw.reg@mfu.ac.th
```

### ขั้นตอนตรวจสอบ

1. เข้าใช้งานบัญชีอีเมล แล้วตรวจสอบว่ามีข้อความแจ้งเตือนหรือรายการที่ต้อง Validate หรือไม่ โดยเฉพาะข้อความหรือสถานะที่แสดงเป็นสีแดง
2. ตรวจสอบการตั้งค่า **Allow less secure apps** ของบัญชีจากลิงก์ต่อไปนี้:
   [Google Account — Less secure apps](https://myaccount.google.com/lesssecureapps?pli=1)
3. หลังแก้ไขการตั้งค่า ให้ทดสอบส่งอีเมลจากระบบถอนรายวิชาอีกครั้ง
4. หากยังส่งไม่ได้ ให้ตรวจสอบ SMTP configuration, App Password, การยืนยันตัวตนแบบ 2 ขั้นตอน และ Log/Error จากระบบเพิ่มเติม

> **ข้อมูลสำคัญ:** ไม่ควรบันทึกรหัสผ่านของบัญชีอีเมลไว้ในไฟล์คู่มือหรือ Git repository ให้ขอรหัสผ่านจากผู้ดูแลระบบ หรือจัดเก็บและเรียกใช้ผ่าน Secret Manager/Password Manager ที่หน่วยงานกำหนด
